NEED4SPACE — MASTER BUILD PROMPT FOR CLAUDE CODE

You are Claude Code. Build Need4Space: a browser anti-gravity racer in space (WipEout / Redout lineage) in plain ES modules + three.js r170, no build step. This document is a reverse-engineered specification of an existing 191-commit project, ordered the way the project was actually built. Build it in the same order, phase by phase, committing at the end of each phase. The game must run and be playable after every phase.

Authorisation note: the owner of the original repo gave permission for this reconstruction. Use your own copyright line / owner name where the original's appears (placeholder <OWNER>); do not embed anyone's personal payment or donation links.

0. OPERATING RULES (read first, obey throughout)
Work phase by phase (P0 → P13). Do not start a phase until the previous one runs in a desktop browser with zero console errors. After each phase: run it, verify with the acceptance checks listed in the phase, git commit with the given message style, tick the phase in NOTES.md.
Never ask questions. When something is ambiguous, pick the most reasonable option, and record the assumption under ## Assumptions in NOTES.md.
Write big files in several tool calls (create the file with the first section, append the rest). Never try to emit a 1,500-line module in one shot. Keep each module under ~1,800 lines.
No build step, no bundler, no npm runtime dependencies. The game is index.html + src/*.js ES modules + src/ui.css + assets/. three.js and meshoptimizer come from the jsDelivr CDN through an import map. Dev tooling (Python) is allowed in tools/.
Everything is procedural unless stated. Ships, tracks, terrain, textures, music and engine sounds are all generated in code (GPU bakes at load, canvas textures, WebAudio synthesis). The original used Blender-baked GLB ships; you do not have those. See §3.2 for how to substitute (procedural ships built from code, with a GLB loading path left in place).
Comment like the original. Every non-trivial block carries a why comment: the symptom it fixed or the design intent (often a quoted user request such as // "make turns harder at higher speeds"). Constants carry units (m, m/s, m/s2, deg). This is a hard style requirement — future-you debugs from these comments.
Physics is track-space, fixed-step 120 Hz, rendered by interpolation (§A). Never couple gameplay to frame rate.
Performance is a feature. Anything per-frame must avoid allocation (module-level scratch Vector3/Quaternions, e.g. _H, _R, _B, _F, _M, _Q). GPU particle systems compute motion in vertex shaders from a seed and the clock. Expensive static work is baked once at load.
Test hooks are mandatory (window.__feather, §N) so the game can be driven headlessly: state(), advance(seconds), shot(name).
Keep a version + changelog (src/changelog.js, newest first) and bump it in the commits indicated below. The title screen shows the latest entry.
1. PRODUCT DEFINITION

An anti-gravity racer. You pilot a hover-racer (Feather S1; later Comet R1 and Anvil H1) against eight AI rivals (nine ships on the grid, player in slot index 4) for three laps on one of five circuits, each a different world:

3. GLOBAL ARCHITECTURE
3.1 World interface (every circuit implements it)

main.js is map-agnostic. A world class (SpaceWorld, ForestWorld, IceWorld, DesertWorld, OceanWorld, MeadowWorld) is constructed with (scene, renderer, camera) and exposes:

name, sunDir, track (a Track), minimap (= track; needs n, px[], pz[]), startIndex
sky (Scene) + skyCam (PerspectiveCamera, near 50, far 200000): backdrop rendered first in its own depth range
sun, sunMid, sunFar: three DirectionalLights = three shadow cascades (e.g. ice: half 10 / 45 / 170 m, near/far 300–500 / 250–550 / 100–900; 4096² maps)
lamps[]: 3 point lights moved to the nearest gantries (fixed count: no shader recompiles mid-race)
headlight config {pos, at, angle, penumbra, distance} (optional), headlightK, nightLights, exposure, exposureK, grade
noAO[], aoOccluders (set of meshes carrying baked wall AO in the normal-pass alpha), worldOnly
lightShafts (bool: enables the god-ray pass), heat (heat-shimmer), dust, thunder, underK (underwater factor), inFall, renderScale, ready
update(t, camera, shipPos, s, renderer), preRender(renderer), follow(p, camera), shadowMode(size, renderer), setOptions(settings), wetCheck()
race back-reference (set by main) so a world can read ships (ice wakes, ocean spray)

Layers: 0 default; 2 = seen but in no cascade (scenery); 3 = far depth slice only; 4 = near depth slice only; 6 = casts only into the world's one-shot static shadow map. The scene is rendered through LayeredRenderPass: sky scene → far slice → near slice (a two-slice depth range so far scenery stays precise out to 30 km: camera near 0.2, far 30000).

3.2 Assets policy (what to do without Blender)

The original ships were modelled and texture-baked in Blender and loaded as GLB with custom node metadata (userData.motion = {type:'spin'|'fold'|'hinge'|'orbit'|'ball', axis, rpm|deg, idle, spool, phase}, userData.pulse = {stage, stages}, userData.light = lamp kind, material names Glass, BayGlass, parts atlases with userData.parts). Reproduce the ships procedurally in src/shipmodels.js (new file): build each ship from lathe/extrude/box/cylinder geometry with named materials and the same metadata conventions, so Ship (§C) treats a procedural ship and a future GLB identically. Provide loadShip(urlOrBuilder) that accepts either. Requirements per ship:

Feather S1: 13.34 m long, ~10.3 m span (half span ≈ 5.15), twin turbofan pods on swept wings, smoked canopy, red livery panels over white, 2 engine rings + rotors (spin), bay glass with avionics.
Comet R1: titanium manta on two hover sponsons, ONE big rocket in a long tail cone, 18-tooth petal nozzle (teeth fold: fanned out engine-off/braking, closed on throttle, rotor spins faster with speed/boost), low faired canopy, pointed nose.
Anvil H1: wider heavy lifting body, two pulse engines in housings, magnet balls orbiting each (orbit/ball), headlamp band across the nose (headLampPos), canopy.
All share the same lowest point (ship.bottom) so hover and chase camera treat them alike; each exposes halfSpan, length, power, ready, engineOn, canopyT, rotors, canopy, plumes, tris, root (physics transform), visual (bob/shake, never fed back).
Livery = {livery:[r,g,b] replaces the red, body:[r,g,b] multiplies the white} via a shader patch; 3 paints per ship (§J.4). Everything else that was a GLB in the original (station.glb ring station, keeper.glb colossus statue) is built procedurally too (or omitted behind its setting).
3.3 Shader strategy
Standard three.js materials, patched with onBeforeCompile chunks installed once, before the first lit material compiles, by patchShaders() in look.js (§F.1). Programs are keyed so presets/quality switches don't collide (customProgramCacheKey).
World-position procedural surfaces: every face carries its own metre coordinates (hullUV = u metres across, v metres along; hullF = width + kind; hullT = u direction; ruins/atlantis use 'fac' = along, up, kind) and the fragment shader draws plates, bolts, windows, grime per pixel. No tiling textures for structure.
Rocks/terrain: one tile painted once on the GPU, projected from 3 world axes at 3 scales, hex-tiled (Mikkelsen 2022: three randomly rotated/shifted copies blended by height).
Specular anti-aliasing (Kaplanyan & Hoffman 2016) in track materials: kr = min(0.5*(dot(dFdx(n),dFdx(n))+dot(dFdy(n),dFdy(n))), 0.18); roughness = sqrt(min(roughness² + kr, 1)).
Deferred bakes: bakeLater() queues a GPU draw; runBakes() compiles all their shaders in parallel (KHR_parallel_shader_compile) then draws them one at a time, awaiting the GPU after each (no multi-second single submission; integrated GPUs are 15–100× slower and Windows resets drivers past ~2 s).
3.4 Loop and timing (main.js)
frame(now): dt = min(0.1, raw); slow.step(dt) returns the game-time scale (slam slow-motion); tick(dt*k); render(). Paused: tick(0) and the scene is drawn only twice after anything changes (pausing, setting, resize) then left still.
tick: read input → menu filter → engine/canopy/camera/help/reset/respawn hotkeys → fixed 120 Hz physics loop (FIXED = 1/120, accumulate; before each step call keep(m) to store previous pose; every mover = all race entries' racers + the controller) → per-frame visuals using between(m, alpha) (lerp pos, slerp quat) so 144 Hz displays don't judder.
scene.matrixWorldAutoUpdate = false; scene.updateMatrixWorld() once per frame in render() (not once per each of the six scene renders).
Rendering: EffectComposer over a half-float target (no depth buffer; MSAA only in the first pass).
3.5 Events

TrackRacer.emit({type,...}) pushes to racer.events; Race.onRacerEvent translates to race events (padfx, fall, drift, driftStart, driftTier, driftChain, flip, scrape, wallfx, damage, wreck, lap, finish, go, slam…) consumed in main.js by FX, audio, HUD. One event per knock (cooldown 0.25 s) — never one per grinding step.

4. ENGINEERING CONVENTIONS
Module-level scratch objects; damp(k, dt) = 1 - exp(-k*dt)-style exponential smoothing for every follower; clamp, smoothstep, mulberry32(seed), noise2, fbm live in noise.js (deterministic value noise + seeded PRNG; seeds fixed so tree scatter, rival grid and track dressing are identical every load).
Settings persisted to localStorage key feather.settings.v4 (§I). Each look feature has its own switch. Changing quality mid-session rebuilds every shader at once in the menu (a "warming" state: no draws while programs compile).
Version-stamped modules: tools/stamp.py (pre-commit hook) writes the import map in index.html with ?v=<sha1[:8] of file> per module and CSS, adds <link rel="modulepreload"> for every module (local stamped URLs + three's files from CDN, listing three's nested imports of EffectComposer, OutputPass, SMAAPass, GTAOPass, GLTFLoader), and prints a build id shown in Settings. Dev-only modules (profile.js, load-worker.js) are not preloaded. Reason: GitHub Pages caches files for 10 minutes, phones ran half-old code.
Ship-specific physics numbers live in HANDLING (ships.js), never in track.js.
Player assistance by difficulty lives in PERKS; rivals get none.
Never invent text/numbers/signs on in-world surfaces ("No text, numbers, signs or markings anywhere").
Every bug the original fixed is documented in a comment next to the fix; where this spec says "(was …)" the original bug is described so you do not reintroduce it.
